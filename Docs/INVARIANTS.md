# System contracts

These contracts are supported by implementation/tests or the existing subscriber
integration agreement. Operational requirements are labeled where enforcement is
outside the proxy. A test reference is a verification target, not a claim that
every possible case has coverage; see [DEVELOPMENT.md](DEVELOPMENT.md) for results.

## File and application ownership

| Rule and why | Implementation / affected consumers | Verify |
| --- | --- | --- |
| Published asks are immutable; workers preserve `job.json` and declared inputs. This prevents partial-input execution and identity drift. Application owns publication; proxy owns queue moves. | [validation.py](../file_proxy/validation.py): `validate_job_folder`; [engine.py](../file_proxy/engine.py): `_process_file_job` validates again after worker. Affects publishers/workers/harvesters. Immutability itself is an integration contract, not OS write protection. | Proxy success, incomplete-sync, invalid-identity, unsafe-worker-output tests; inspect worker integration when changing inputs. |
| Inventoried bytes must match before execution. Missing/mismatched manifest or declared files wait within sync grace; invalid contracts become terminal answers. This accommodates eventual sync. | `validate_file_inventory`, `Proxy._scan`; affects sync timing and error classification. Malformed non-manifest payload JSON is invalid, not deferred. | `test_incomplete_synced_job_waits_until_declared_file_arrives`, `test_incomplete_synced_job_expires_after_grace_period`, invalid-job tests. |
| Identity must match directory and paths must remain inside the envelope under Windows/POSIX checks. API route strings have explicit exemptions. This keeps queue references portable and contained. | `models` validators; `validate_relative_reference`, `_path_values`; affects schemas, worker JSON, symlinks. It is not a general sandbox for trusted worker code. | Proxy invalid jobs, unsafe payload, escaping symlink, and API-route tests. |
| Execute only registered local argv, append `--job-dir`, use `shell=False`. Queue writers do not choose executable code. | `Registry.load`, `WorkerRegistration`, `Proxy._process_file_job`; affects all subscriber commands and cwd/environment. | Registry expansion, success, unknown-worker and launch-failure tests; inspect actual command construction. |
| Single attempt, no automatic worker replay. An interrupted unknown outcome becomes `PROXY_INTERRUPTED`; known journal/result is republished. Avoid duplicate external effects. | `recover_interrupted`, `_publish_completed_running`, `_persist_local_outcome`; affects restart, publication failure, subscriber retries. | Interrupted recovery and launch/timeout/exit tests; journal-publication failure coverage is a gap. |
| Answer results and full inventory must be durably harvested before subscriber retention; retry uses a fresh attempt ID. This is subscriber-owned, not an implemented harvester. | [README contract](../README.md), `ProxyResult`, `_move_to_answer` rejects existing answer. Affects subscriber idempotency and retention. | Integrating app tests must cover duplicate harvest, partial answers, new-ID retry; no subscriber tests here. |

## Scheduling and process safety

| Rule and why | Implementation / affected consumers | Verify |
| --- | --- | --- |
| One assigned proxy per queue; coordinate local instances through the same runtime directory. Local lock is not distributed. Prevent concurrent queue ownership and GPU oversubscription. | `Proxy.lock`, `RuntimeLock` in engine; affects launch configuration, separate runtime dirs/machines. Operational enforcement remains necessary. | Concurrent lock and foreign-host lock tests; inspect current local lock path before modifying deployment. |
| Active expensive work is not preempted. HTTP waits for `finished`; async file-worker shutdown awaits shielded worker. Prevent overlap and half-finished output. | `Proxy.run_scheduler`; [scheduler.py](../file_proxy/scheduler.py): futures and `finish`; supervisor stop. Affects HTTP handlers/lifecycle tasks/TUI. | Scheduler non-preemption, keyed ComfyUI history, and TUI active-worker stop tests. |
| Affinity must not leapfrog an earlier backend block; file affinity stays within highest eligible priority. HTTP cannot overtake the selected older file job when both backends are known and different. Prevent model reuse from starving backend switches. | `Proxy._choose_resource_job/run_scheduler`, `HttpQueue._candidate`; affects ordering, trusted backend declarations, resources. | File/HTTP no-backend-overtaking and parametrized cross-queue older-file tests. Priority interactions need additional coverage for changes. |
| HTTP control mutations are affinity barriers; oldest override and streak bound apply only within the eligible backend prefix. Prevent reordering past evidence-erasing controls. | `HttpProxyService.handle` sets barriers; `HttpQueue._candidate`; affects queue/history POSTs and affinity. | Inspect candidate prefix/barrier selection; direct barrier/oldest-override tests are currently absent. |
| Never adopt or terminate manual ComfyUI. Stop only owned processes, confirm endpoint closure, unload/verify Ollama before managed ComfyUI startup. Protect user processes and GPU residency. | [backend.py](../file_proxy/backend.py): `ensure_comfyui`, `stop_comfyui`, `_unload_ollama`; affects file/HTTP backends, Windows Job Object. | Reliable lifecycle manual-listener, disposable-process, unload-verification tests; real GPU acceptance remains unverified. |
| An external unresolved ComfyUI prompt retains the slot until intervention/shutdown; restart uncertainty blocks new execution. Avoid unsafe inference overlap after ambiguous cancellation. | `HttpProxyService._cancel_and_reconcile/reconcile_records`, `BackendManager.block`; affects downstream timeout, shutdown, restart. | Inspect deadline/cancellation branches; full external-unresolved integration test is a gap. |

## HTTP, persistence, and prompts

| Rule and why | Implementation / affected consumers | Verify |
| --- | --- | --- |
| A ComfyUI prompt has a validated canonical-form UUID and durable uniqueness record before dispatch; the actual returned valid ID can be reconciled. Track one execution rather than unrelated history. | `_prepare_prompt_id`, `_extract_prompt_id`, `ExecutionStore.create/reconcile_prompt_id`; affects prompt clients, keyed cache, history. Reuse protection lasts while metadata is retained. | UUID validation, prompt reuse/reopen, keyed-history slot tests. |
| Prompt POST response completion does not release the slot; the owned lifecycle task waits for keyed history or explicit reconciliation. Client disconnect after dispatch does not discard it. | `handle`, `_run_prompt_lifecycle`, `_wait_for_prompt_completion`; affects scheduler and client cancellation. Parsed keyed dict is considered terminal; success is checked separately. | Keyed-history slot and terminal-ComfyUI-error tests; disconnect paths merit dedicated lifecycle acceptance coverage. |
| Cache artifacts before exposing archived history; terminal errors are not successful renders. Managed original-output deletion requires successful history, owned managed backend, nonempty cache file, and contained output path. | `_archive_completion`, `_archive_artifact`, `_remove_managed_output_duplicates`, `_managed_output_path`; affects history/view clients, output storage/retention. | Terminal error and output-path resolution tests; full cache/delete publication sequence coverage is incomplete. |
| Undispatched HTTP bodies stay memory-only and are never replayed after restart. Durable metadata reconciles outcomes, not requests. Avoid duplicate accepted effects and sensitive payload persistence. | `HttpProxyService`, [store.py](../file_proxy/store.py), `run_http_proxies`; affects overload/cancellation/restart. | Store schema and lifecycle tests; inspect persistence changes for accidental body storage. |
| HTTP diagnostics at current call sites contain no bodies/headers. Captured worker/backend logs have separate contracts. Keep transport observability from copying payloads. | [diagnostics.py](../file_proxy/diagnostics.py), `_write_diagnostic` callers; affects logs/privacy. Logger accepts arbitrary details, so review new call sites. | Daily diagnostic retention and HTTP streaming/disconnect event tests; inspect fields. |
| No proxy-wide system prompt or task inference from alias/worker. Only documented alias effort normalization on `POST /v1/chat/completions`; native routes and unknown inputs stay unchanged. Invalid policy reload keeps last good policy. | [reasoning_policy.py](../file_proxy/reasoning_policy.py), [retained prompt ownership note](../Docs-Joe/System_Prompt_Review.md); affects subscriber prompts, alias metadata and HTTP compatibility. | Reasoning-policy preservation/mapping tests; hot-reload test currently fails in this environment. |

Changes to any contract need an explicit impact analysis covering the listed
consumers and validation gaps; record compatibility changes in data/component
docs and a durable decision when appropriate. Do not silently strengthen these
claims into guarantees the implementation does not provide.
